Each of the following two procedures converts a binary tree to a list.

```racket
(define (tree->list-1 tree)
  (if (null? tree)
      '()
      (append (tree->list-1 (left-branch tree))
              (cons (entry tree)
                    (tree->list-1
                      (right-branch tree))))))

(define (tree->list-2 tree)
  (define (copy-to-list tree result-list)
    (if (null? tree)
        result-list
        (copy-to-list (left-branch tree)
                      (cons (entry tree)
                            (copy-to-list
                              (right-branch tree)
                              result-list)))))

  (copy-to-list tree '()))
```

a. Do the two procedures produce the same result for every tree? If not, how do the results differ? What lists do the two procedures produce for the trees in Figure 2.16?
b. Do the two procedures have the same order of growth in the number of steps required to convert a balanced tree with *n* elements to a list? If not, which one grows more slowly?

## Solution

Let's consider the following tree representation of the set {1, 3, 5, 7, 9, 11} for this problem.

```
       7
      / \
     3   9
    / \   \
   1   5   11
```

The two procedures produce the same results. Assuming that the tree representation of sets satisfies the requirement that:

- all of the nodes in the left subtree are smaller than the entry node, and
- all of the nodes in the right subtree are larger than the entry node,

then they produce ordered lists that arrange the elements of the set in ascending order.

Below are the results produced for the trees displayed in Figure 2.16.

| tree                                            | `tree->list-1`   | `tree->list-2`   |
| ----------------------------------------------- | ---------------- | ---------------- |
| `(7 (3 (1 () ()) (5 () ())) (9 () (11 () ())))` | `(1 3 5 7 9 11)` | `(1 3 5 7 9 11)` |
| `(3 (1 () ()) (7 (5 () ()) (9 () (11 () ()))))` | `(1 3 5 7 9 11)` | `(1 3 5 7 9 11)` |
| `(5 (3 (1 () ()) ()) (9 (7 () ()) (11 () ())))` | `(1 3 5 7 9 11)` | `(1 3 5 7 9 11)` |

Although the outputs are the same, the processes generated by the procedures are different. 

### `tree->list-1`

In the case of `tree->list-1`:

- it takes the tree, 
- produces an ordered list of the left subtree,
- adjoins the entry node, which is greater than all of the elements in the left subtree but lesser than the ones in the right subtree, to the resultant ordered list of the right subtree,
- and appends the right ordered list to the left ordered list


#### Order of Growth of Steps

In the case of a balanced tree, here's how we can estimate the order of growth of steps for `tree->list-1`. Assume that the work required for a set of *n* elements is *W(n)*. It has two subtrees which have a size of *n*/2 each. So, the work required for each subtree is *W(n/2)*. But, we need to append the ordered list created by the right subtree to the ordered list created by the left subtree. Since each of the ordered lists is of size *n*/2, the `append` operation will require an additional *n*/2 steps to copy over the left ordered list.

```
W(n) = 2⋅W(n/2) + n/2
     = 2⋅(2⋅W(n/4) + n/4) + n/2
     = 4⋅W(n/4) + n/2 + n/2
     = 4⋅(2⋅W(n/8) + n/8) + n/2 + n/2
     = 8⋅W(n/8) + n/2 + n/2 + n/2
     = n⋅W(n/n) + (n/2)·log₂(n)
     = n⋅W(1) + (n/2)·log₂(n)
     = O(n) + O(n⋅logn)
     = O(n⋅logn), since n⋅logn grows faster than n
```

Thus, the order of growth of steps for a balanced tree is *O(n⋅logn)*.

In the case of a left-leaning tree:

- the top-most node copies the remaining *n*-1 nodes from the left subtree
- the next node copies the remaining *n*-2 nodes from the left subtree
- ...and so on.

```
1 + 2 + ... + (n-1) = n(n-1)/2
```

So, the order of growth of steps for a left-leaning tree is *O(n²)*.

In the case of a right-leaning tree the cost of an `append` at each stage is virtually 0, because the left subtree is always an empty list. In a binary tree, the total number of recursive calls is equal to the sum of the number of non-null nodes (*n*) and null-nodes (*n* + 1), i.e. 2*n* + 1. In this case, the total number of steps can be equated to the total number of recursive calls, because:

- each non-null call is evaluated to a `cons` operation, which is *O(1)*
- each null call does a null check, which is again *O(1)*

So, the total order of growth is `(2n + 1) · O(1)`, i.e. the order of growth of steps for a right-leaning tree is *O(n)*.

#### Order of Growth of Space

When it comes to the order of growth of space, it is equal to the maximum depth of the tree.

- in a balanced tree, the order of growth is *O(logn)*
- in both left and right leaning trees, the order of growth is *O(n)*

### `tree->list-2`

In the case of `tree->list-2`:

- it takes the tree and an accumulator (that initially starts off as the empty list)
- it adjoins the entry node to the accumulated value produced by the right branch
- and proceeds to split the left branch and passes the new accumulated value (from the previous step) as the accumulator

**Note:** We reach the tipping point in this pattern when we reach the right-most node, i.e. the greatest value. That's when we start adjoining values to the accumulator and move towards the left.

```racket
(copy-to-list '(7 (3 (1 () ()) (5 () ())) (9 () (11 () ()))) '())

(copy-to-list '(3 (1 () ()) (5 () ())) 
              (cons 7
                    (copy-to-list '(9 () (11 () ())) '())))

(copy-to-list '(3 (1 () ()) (5 () ())) 
              (cons 7
                    (copy-to-list '()
                                  (cons 9
                                        (copy-to-list '(11 () ())
                                                      '())))))

(copy-to-list '(3 (1 () ()) (5 () ()))
              (cons 7
                    (copy-to-list '()
                                  (cons 9
                                        (copy-to-list '()
                                                      (cons 11
                                                            (copy-to-list '() '())))))))

(copy-to-list '(3 (1 () ()) (5 () ()))
              (cons 7
                    (copy-to-list '()
                                  (cons 9
                                        (copy-to-list '()
                                                      (cons 11
                                                            '()))))))

(copy-to-list '(3 (1 () ()) (5 () ()))
              (cons 7
                    (copy-to-list '()
                                  (cons 9
                                        (copy-to-list '()
                                                      (list 11))))))

(copy-to-list '(3 (1 () ()) (5 () ()))
              (cons 7
                    (cons 9
                          (list 11))))

(copy-to-list '(3 (1 () ()) (5 () ()))
              (cons 7
                    (list 9 11)))

(copy-to-list '(3 (1 () ()) (5 () ()))
              (list 7 9 11))

(copy-to-list '(1 () ())
              (cons 3
                    (copy-to-list '(5 () ())
                                  (list 7 9 11))))

(copy-to-list '(1 () ())
              (cons 3
                    (copy-to-list '()
                                  (cons 5
                                        (copy-to-list '()
                                                      (list 7 9 11))))))

(copy-to-list '(1 () ())
              (cons 3
                    (copy-to-list '()
                                  (cons 5
                                        (list 7 9 11)))))

(copy-to-list '(1 () ())
              (cons 3
                    (copy-to-list '()
                                  (list 5 7 9 11))))

(copy-to-list '(1 () ())
              (cons 3
                    (list 5 7 9 11)))

(copy-to-list '(1 () ())
              (list 3 5 7 9 11))

(copy-to-list '()
              (cons 1
                    (copy-to-list '()
                                  (list 3 5 7 9 11))))

(copy-to-list '()
              (cons 1
                    (list 3 5 7 9 11)))

(copy-to-list '()
              (list 1 3 5 7 9 11))

```

#### Order of Growth of Steps

Although there are 2 recursive calls made at each step, it's the inner call that gets evaluated first, and it builds a single chain of deferred operations. So, this procedure is linear recursive in nature. In total, there are 2*n*+1 calls (as discussed above), and the work done by each call is mainly adjoining the node to the accumulator. Hence, the order of growth of steps is *O(n)*.

#### Order of Growth of Space

The order of growth of space for `tree->list-2` is different for the 3 possible types of trees: balanced, left-leaning, and right-leaning. This procedure, unlike `tree->list-1` builds the result starting from the right-most node, i.e. the greatest value, and then accumulating the values in the left subtree. So, the longest chain of deferred operations is created when we hit the greatest value.

In the case of a left-leaning tree, the entry node will always be the greatest value. The right subtree is always empty, so the application of `copy-to-list` on the right subtree immediately resolves and the current node's value is adjoined to the accumulator to give us the new accumulator value to be used for the next node, i.e. entry node of the left subtree. The process doesn't build a chain of deferred operations because of this reason, regardless of the size of the set. Thus, the order of growth of space in this case is *O(1)*.

```racket
(tree->list-2 '(5 (3 (1 () ()) ()) ()))

(copy-to-list '(3 (1 () ()) ())
              (cons 5
                    '()))

(copy-to-list '(3 (1 () ()) ())
              '(5))

(copy-to-list '(1 () ())
              (cons 3
                    (copy-to-list '() '(5))))

(copy-to-list '(1 () ())
              (cons 3
                    '(5)))

(copy-to-list '(1 () ())
              '(3 5))

(copy-to-list '()
              (cons 1
                    (copy-to-list '() '(3 5))))

(copy-to-list '()
              (cons 1
                    '(3 5)))

(copy-to-list '()
              '(1 3 5))

(1 3 5)
```

In the case of a right-leaning tree, we end up with a deferred chain of operations because we traverse through each of the right subtrees until we hit the right-most node, i.e. the largest value. In a right-leaning tree, this means that we have to traverse through the entire set to reach this node. So, the order of growth of space is *O(n)*.

```racket

                    (copy-to-list '(3 () (5 () ()))

(copy-to-list '()
              (cons 1
                    (copy-to-list '()
                                  (cons 3
                                        (copy-to-list '(5 () ())
                                                      '())))))

(copy-to-list '()
              (cons 1
                    (copy-to-list '()
                                  (cons 3
                                        (copy-to-list '()
                                                      (cons 5
                                                            (copy-to-list '()
                                                                          '())))))))

(copy-to-list '()
              (cons 1
                    (copy-to-list '()
                                  (cons 3
                                        (copy-to-list '()
                                                      (cons 5
                                                            '()))))))

(copy-to-list '()
              (cons 1
                    (copy-to-list '()
                                  (cons 3
                                        (copy-to-list '()
                                                      '(5))))))

(copy-to-list '()
              (cons 1
                    (copy-to-list '()
                                  (cons 3
                                        '(5)))))

(copy-to-list '()
              (cons 1
                    (copy-to-list '()
                                  '(3 5))))

(copy-to-list '()
              (cons 1
                    '(3 5)))

(copy-to-list '()
              '(1 3 5))

(1 3 5)
```

In a balanced tree, it takes us a total number of traversal steps (and a maximum number of deferred operations) of the order log₂*n* in order to reach the right-most node. So, we can conclude that the order of growth of space in this case is *O(logn)*.

### Comparison

| tree             | `tree->list-1` steps | `tree->list-1` space | `tree->list-2` steps | `tree->list-2` space |
| ---------------- | -------------------- | -------------------- | -------------------- | -------------------- |
| balanced         | *O(n·logn)*          | *O(logn)*            | *O(n)*               | *O(logn)*            |
| left-leaning     | *O(n²)*              | *O(n)*               | *O(n)*               | *O(1)*               |
| right-leaning    | *O(n)*               | *O(n)*               | *O(n)*               | *O(n)*               |

`tree->list-2` grows more slowly for a set with *n* elements that is represented by a balanced binary tree.
